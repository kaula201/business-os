**კოდი:** `security`
**Route:** `/security`
**კატეგორია:** operations
**დამოკიდებულია:** `settings`
**გვერდი:** `frontend/src/pages/SecurityPage.tsx` (311 სტრიქონი)
**Backend:** `security.py`, `field_access.py`

---

## მიზანი

სისტემის უსაფრთხოების მართვა: ორფაქტორიანი ავტორიზაცია (2FA), შესვლის ისტორია, ველების დონეზე წვდომის კონტროლი (field-level access), RBAC წესები.

## გვერდის სტრუქტურა

### 1. ორფაქტორიანი ავტორიზაცია (2FA)

| ელემენტი | ტიპი | ფუნქცია |
|----------|------|----------|
| „ჩართვა" | ღილაკი | 2FA-ს აქტივაცია მიმდინარე მომხმარებლისთვის |
| „გამორთვა" | ღილაკი | 2FA-ს დეაქტივაცია |

### 2. ველების წვდომის წესები (Field Access)

| ელემენტი | ტიპი | ფუნქცია |
|----------|------|----------|
| „ახალი წესი" | ღილაკი | წესის შექმნის ფორმა |
| „შექმნა" | ღილაკი | წესის შენახვა (`fieldAccessApi.create`) |
| წესის რიგი | ცხრილი | მოდული, როლი, ველი, ხილვადობა |

### 3. წესის ფორმა

| ველი | ტიპი | შესაძლო მნიშვნელობები |
|------|------|------------------------|
| მოდული | select | clients / orders / invoices / inventory / hr / ... |
| როლი | select | admin / manager / employee / accountant |
| ველი | input | ველის სახელი (მაგ. `phone`) |
| ხილვადობა | select | ჩანს / დამალული / მხოლოდ წაკითხვადი |

## API Endpoints

### ველების წვდომა (`field_access.py`)

| მეთოდი | Path | ფუნქცია | აღწერა |
|--------|------|---------|--------|
| GET | `/field-access/` | `list_rules` | წესების სია |
| POST | `/field-access/` | `create_rule` | წესის შექმნა |
| DELETE | `/field-access/{rule_id}` | `delete_rule` | წესის წაშლა |

## Frontend API ზარები

- `fieldAccessApi.list()` → GET `/field-access/`
- `fieldAccessApi.create(fieldForm)` → POST `/field-access/`
- `fieldAccessApi.remove(id)` → DELETE `/field-access/{id}`

## ბიზნეს ლოგიკა

- **Field-level access:** განსაზღვრავს, რომელი როლი რომელ ველს ხედავს კონკრეტულ მოდულში (მაგ. მენეჯერს არ უნდა ენახოს ხელფასის ველი)
- **2FA:** დამატებითი დაცვა შესვლისას
- **RBAC:** მოდულის დონეზე უფლებები (can_access/create/edit/delete/approve) იმართება მოდულების სისტემაში
