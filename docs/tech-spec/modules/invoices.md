# მოდული: Invoices (გაყიდვის ინვოისები)

**კოდი:** `invoices`
**Route:** `/invoices`
**კატეგორია:** sales
**დამოკიდებულია:** `orders` (გაყიდვის შეკვეთები)
**გვერდი:** `frontend/src/pages/InvoicesPage.tsx` (347 სტრიქონი)
**Backend:** `invoices.py`, `invoices_enhanced.py`

---

## მიზანი

გაყიდვის ინვოისების სრული სასიცოცხლო ციკლი: შექმნა შეკვეთიდან, draft-ში რედაქტირება, დადასტურება (issue), ექსპორტი (PDF/Word/Excel). დადასტურებისას იქმნება დავალიანება და GL გატარება.

## გვერდის სტრუქტურა

### 1. სიის ხედი (List)

| ელემენტი | ტიპი | ფუნქცია |
|----------|------|----------|
| სტატუსის ფილტრი (ყველა / შესავსები / დადასტურებული) | ღილაკების ჯგუფი | ფილტრავს სიას `status` პარამეტრით |
| ინვოისის რიგი | ცხრილი | ნომერი, კლიენტი, თარიღი, თანხა, სტატუსი |
| „შევსება" (draft) / „ნახვა" (issued) | ღილაკი | ხსნის ინვოისს რედაქტირების ან ნახვის რეჟიმში |

### 2. ინვოისის დეტალები (ნახვის რეჟიმი)

| ელემენტი | ტიპი | ფუნქცია |
|----------|------|----------|
| ინვოისის ნომერი + შეკვეთის ნომერი | ტექსტი | იდენტიფიკაცია |
| „PDF ნახვა" | ღილაკი | ხსნის PDF პრევიუ (`GET /invoices/{id}/preview`) |
| „რედაქტირების გაგრძელება" (draft-ზე) | ღილაკი | გადადის რედაქტირების რეჟიმში |
| „დადასტურებული დოკუმენტი" ბლოკი (issued-ზე) | ინფორმაცია | ფინანსური მონაცემები დაფიქსირებულია |
| „PDF ჩამოტვირთვა" | ღილაკი | `GET /invoices/{id}/download` |
| „Word ჩამოტვირთვა" | ღილაკი | `GET /invoices/{id}/download-word` |
| „Excel ჩამოტვირთვა" | ღილაკი | `GET /invoices/{id}/download-excel` |

### 3. რედაქტირების რეჟიმი (draft)

#### 3.1. პოზიციები (Items)

| ელემენტი | ტიპი | ფუნქცია |
|----------|------|----------|
| „დამატება" | ღილაკი | ამატებს ახალ პოზიციას (`addItem`) |
| დასახელება | input | პროდუქტის სახელი |
| რაოდენობა | input (number) | min 0.001, step 0.001 |
| ფასი | input (number) | min 0, step 0.01 |
| ფასდაკლება % | input (number) | 0-100 |
| დღგ % | input (number) | 0-100 |
| წაშლა (Trash) | ღილაკი | შლის პოზიციას (ბოლო პოზიციის წაშლა აკრძალულია) |

#### 3.2. მოქმედებები

| ღილაკი | ფუნქცია |
|--------|----------|
| „ცვლილებების შენახვა" | ინახავს draft-ს (`PATCH /invoices/{id}/draft`) |
| „შენახვა და PDF ნახვა" | ინახავს და ხსნის PDF პრევიუს |
| „დადასტურებაზე გადასვლა" | ხსნის დადასტურების დიალოგს |

### 4. დადასტურების დიალოგი

| ელემენტი | ტიპი | ფუნქცია |
|----------|------|----------|
| გაფრთხილება | ტექსტი | „დადასტურების შემდეგ ფინანსური მონაცემები ჩაიკეტება და შეიქმნება დავალიანება და GL გატარება" |
| „დიახ, დაადასტურე" | ღილაკი | `POST /invoices/{id}/issue` — ქმნის დავალიანებას + GL გატარებას |
| „უკან დაბრუნება" | ღილაკი | ხურავს დიალოგს |

### 5. PDF პრევიუ

- iframe-ში ჩაშენებული PDF
- „სრულ ეკრანზე / ბეჭდვა" ღილაკი — ხსნის ახალ ტაბში

## ბიზნეს ლოგიკა

- **Draft → Issued:** დადასტურებისას იკეტება ფინანსური მონაცემები, იქმნება მოვალეობა კლიენტზე და GL გატარება
- **შეკვეთასთან კავშირი:** ინვოისი იქმნება შეკვეთიდან (`order_number` ჩანს დეტალებში)
- **ფასდაკლება და დღგ:** თითო პოზიციაზე ცალ-ცალკე ითვლება
- **ვალიდაცია:** მინიმუმ 1 პოზიცია სავალდებულოა (`validDraft`)
