## მიზანი

## API Endpoints

| მეთოდი | Path | ფუნქცია | აღწერა |
|--------|------|---------|--------|
| GET | `/clients/` | `list_clients` | სია (ფილტრები: search, status, page) |
| GET | `/clients/{client_id}` | `get_client` | ერთი კლიენტი |
| POST | `/clients/` | `create_client` | შექმნა |
| PATCH | `/clients/{client_id}` | `update_client` | განახლება |
| DELETE | `/clients/{client_id}` | `delete_client` | წაშლა (soft delete) |
| POST | `/clients/{client_id}/interactions` | `add_interaction` | ინტერაქციის დამატება |

## Frontend API ზარები

- `clientsApi.list({search})` → GET `/clients/`
- `clientsApi.create(data)` → POST `/clients/`
- `clientsApi.update(id, data)` → PATCH `/clients/{id}`
- `clientsApi.delete(id)` → DELETE `/clients/{id}`

## ბიზნეს ლოგიკა

- **Soft delete:** წაშლა აყენებს `deleted_at`-ს, ჩანაწერი რჩება ბაზაში
- **უნიკალურობა:** საიდენტიფიკაციო კოდი უნიკალურია კომპანიის ფარგლებში
- **კავშირები:** კლიენტი არის საფუძველი შეკვეთების, ინვოისების, CRM-ისთვის
